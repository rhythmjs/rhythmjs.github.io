Security middleware

CORS, CSRF protection, and secure headers for Rhythm routers.

Install #

The package provides three independent middleware modules. Each module is its own subpath export; there is no root barrel export. Mount any of them with use() on a router or app.

CORS #

@rhythmjs/security/cors sets the Access-Control-* headers on every response and answers preflight OPTIONS requests with 204 before the router runs. The origin option accepts the wildcard "*" (the default), a single origin string, an array of origins, or an (origin) => string | null function. A non-wildcard origin is echoed back only when the request origin matches, and Vary: Origin is appended so caches keep responses separate per origin.

Set credentials to allow cookies, exposeHeaders to make response headers readable from scripts, and maxAge to cache preflight results.

CSRF protection #

@rhythmjs/security/csrf blocks cross-site form submissions by checking the Origin header. An unsafe method (anything other than GET or HEAD) with a form content type (application/x-www-form-urlencoded, multipart/form-data, or text/plain) and a missing or unallowed Origin is rejected with 403. JSON and other non-form content types pass through, because cross-site pages cannot send them without a CORS preflight.

By default only same-origin form posts are allowed: the origin must equal the request URL's own origin. The origin option accepts a string, an array of strings, or an (origin) => boolean predicate naming the allowed origins.

Secure headers #

@rhythmjs/security/secure-headers applies helmet-style security headers to every response after the handlers run. Ten headers are set by default, including X-Frame-Options: SAMEORIGIN, X-Content-Type-Options: nosniff, and Strict-Transport-Security. Every option accepts a string to override the value or false to drop the header. contentSecurityPolicy and crossOriginEmbedderPolicy are off by default and set only when configured.

See the API reference for every option and its default value.
