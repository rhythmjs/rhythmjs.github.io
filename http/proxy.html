Proxy & i18n

Talk to upstreams and users in their own terms: a fetch-based reverse proxy with careful header hygiene, and per-request language negotiation over any i18next.

A reverse proxy on fetch #

proxy(options) relays the request to target on plain fetch and web streams - request and response bodies stream without buffering (the outgoing request uses duplex: "half"; GET/HEAD go bodiless). It is a terminal middleware: it writes the upstream response and does not call downstream handlers.

Header hygiene and x-forwarded-* #

Hop-by-hop and framing headers (connection and everything it names, transfer-encoding, upgrade, …) are stripped in both directions, along with host, accept-encoding, and proxy credentials; forwardHeaders re-allows specific ignored request headers and filterHeaders drops extra ones. headers sets fixed values on every upstream request.

With xfwd (on by default) the client IP, request.ip when your Bun.serve fetch exposes it via server.requestIP(), is appended to the inbound x-forwarded-for chain, while x-forwarded-proto/-host/-port are overwritten with server-resolved values, so a client-supplied value never reaches the upstream.

Redirects and cookies #

Redirects are manual by default and rewritten on the way back: with locationRewrite: true (default), a Location or Refresh pointing at the target origin is mapped onto the request origin; a { prefix: replacement } map rewrites by prefix; false passes through. Upstream Set-Cookie headers are appended verbatim unless cookieDomainRewrite / cookiePathRewrite remap them: a string rewrites everything, a map matches exact values with a "*" wildcard, and an empty replacement removes the attribute.

Failure modes #

Upstream failures map to JSON error responses: an exceeded timeout aborts the fetch and answers 504; a client disconnect answers 499; any other network error answers 502. The fetch option injects a custom fetch, the seam tests and service meshes use.

Language negotiation with i18next #

i18n({ i18next, ... }) puts a per-request translator on the context: ctx.t, ctx.language, and the scoped instance as ctx.i18n (I18nContext). The instance contract is structural (I18nInstanceLike: only t is required) and every optional member is feature-detected, so i18next major versions cannot break compilation. Per-request isolation prefers cloneInstance(), then getFixedT(language), then a shared changeLanguage(); an uninitialized instance is init()-ed once, lazily.

Detection order and matching #

Candidates are tried per source in detection.order - default querystring (?lng=), cookie (i18next), then the Accept-Language header parsed with q-values; a path source reads a configurable segment index. The first source that yields candidates wins. Matching against the supported list (from options, or read off the instance) is case-insensitive and falls from exact tag to base language in both directions (de-AT ↔ de), then to the fallback language.

With cacheCookie: true the resolved language is written back to the lookup cookie (one-year Max-Age) whenever it changed, and unless disabled the response gains a content-language header. parseAcceptLanguage(header) and detectLanguage(request, options?) are exported standalone.
