HTTP utilities

Cookies, sessions, caching, timeouts, and body limits for Rhythm routers.

Install the package #

@rhythmjs/http ships utility middleware for Rhythm routers and handlers. Each module is exported by its own subpath; there is no root barrel export. Import only the pieces you use.

Read and write cookies #

cookies() parses the request Cookie header and exposes a Cookies jar on the context, typed by CookiesContext. Read with get(name) and getAll(); write with set(name, value, options?), which defaults to Path=/, and delete(name), which sets Max-Age=0. Each set() call emits its own Set-Cookie header.

Keep a session #

session() provides cookie-based sessions with a pluggable SessionStore. The bundled MemoryStore is the default and suits a single process. The session cookie (sid by default; HttpOnly, SameSite=Lax, Path=/) is only written when the session is first used.

ctx.session.destroy() deletes the stored session and expires the cookie. Unknown or expired session ids get a fresh session, so a forged cookie value is never trusted as-is.

Cache with etags #

etag() adds an ETag header derived from the response body with SHA-1 and answers 304 Not Modified when the request's If-None-Match matches the tag. Only successful (2xx) string bodies are tagged, and a pre-set ETag header is left alone. Pass { weak: true } to emit W/"..." tags.

Enforce a deadline #

timeout(ms) fails requests that exceed the deadline with a 504 { "success": false, "status": 504, "message": "Gateway Timeout" } JSON body. Downstream errors still propagate as errors; only the deadline produces a 504. The downstream work is not aborted, its result is discarded.

Limit request bodies #

bodyLimit(maxBytes) rejects request bodies larger than the byte limit with 413 Payload Too Large. It checks Content-Length first when the header is present; otherwise it measures a clone of the request body before calling the next middleware.
