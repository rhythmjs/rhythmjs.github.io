Quick start

Clone the starter template, run it, and grow it into your application.

Clone the template #

Start from the template repository rather than wiring a project up file by file: it is a minimal, runnable application organized the way NestJS organizes its starter, expressed with Rhythm primitives. Clone it, or press GitHub's "Use this template" button. Every package is ESM and runs on Bun 1.2 or newer; the ecosystem is built on Bun's native APIs, with no runtime adapters.

Run it #

Install the dependencies and start the watcher; the server answers on port 3000.

What’s inside #

Five small files cover the whole Nest-style pattern: a module, a controller, a service, a spec, and your own server entry point.

The pattern #

The service holds business logic and knows nothing about HTTP. The module provides it with provide(), which places it on the request context of everything mounted afterwards. The controller declares that dependency in its context type, so handlers use ctx.appService with full type safety: the type-level equivalent of constructor injection.

Test it #

The controller spec builds a small test harness instead of booting the whole application: a fresh Rhythm provides the service, mounts the controller's routes, and is wrapped in a fetch handler. Substituting a stub service proves the controller delegates instead of hardcoding responses.

Grow the app #

Add a feature by repeating the pattern: a users.service.ts, a users.controller.ts router with a prefix, provide the service in the module, and mount the controller before the 404 handler. Validation, sessions, logging, CORS, and friends come from the Middleware, HTTP, Security, and Observability packages.

Under the hood #

There is no scaffolding magic in the template: it is just the kernel and the router, which you could install and wire up yourself.

The kernel alone composes middleware over any input. Providers initialize once; middleware runs per input; the typed context carries both.

Serve HTTP #

The router registers routes with named parameters and mounts into a Rhythm host app via middleware(); a plain Bun.serve call, written by you in your own main.ts, starts the host app. Run it with bun src/main.ts.

Add validation #

Ecosystem packages drop into the same chain. Here validate checks the body against a zod schema and exposes the typed output as ctx.valid.body; an invalid body answers 400 before the handler runs.

Where to go next #

Read the philosophy, or browse the package groups in the sidebar: Middleware, HTTP, Security, and Observability each document their modules and full API.
