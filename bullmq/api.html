API reference

Every export of @rhythmjs/bullmq and @rhythmjs/bullmq/types: the service factory and kernel module, the BullMQ-typed options, and the underlying Queue escape hatch.

createQueueService and bullmqModule #

createQueueService constructs one BullMQ Queue from the options; every process() call adds a Worker on the same queue name and shared connection. bullmqModule.forRoot (module name bullmq) provides { queueService } and disposes it on teardown, workers first, then the queue.

BullmqModuleOptions
{ name?: string; connection?: ConnectionOptions; prefix?: string; defaultJobOptions?: JobsOptions }. connection defaults to { host: "127.0.0.1", port: 6379 }; prefix is BullMQ's Redis key prefix.

QueueService<TJobs> #

add(name, payload, options?)
queue.add with the typed payload as job data; resolves to BullMQ's job id (string | undefined).
addBulk(jobs)
queue.addBulk, mapping each entry's payload to data and options to opts; resolves to the ids in order.
schedule(name, repeat, payload, options?)
queue.upsertJobScheduler(name, repeat, template) - the scheduler id is the job name, and the template carries the payload and options for each spawned job. Calling it again with the same name replaces the schedule.
unschedule(name)
queue.removeJobScheduler(name).
process(processors, options?)
Creates a BullMQ Worker on the queue name with the shared connection/prefix and options.concurrency. The worker's processor dispatches by job.name to the typed handler, passing (payload, { id, name, attemptsMade }); an unregistered name throws no processor registered for job "name", which lands in BullMQ's retry/failed flow. Returns a handle whose close() closes the worker and deregisters it.
counts()
queue.getJobCounts(): BullMQ's state counts (waiting, active, delayed, completed, failed, …).
close()
Closes every open worker, then the queue and its connection.
queue
The underlying BullMQ Queue instance, for everything the facade does not cover.

Options and types #

JobsOptions / RepeatOptions / ConnectionOptions
Re-exported from bullmq unchanged; the facade adds no translation layer. JobsOptions covers delay, attempts, backoff, priority, removeOnComplete/removeOnFail, jobId, lifo, deduplication, and the rest; RepeatOptions covers pattern, every, tz, limit, …
ProcessOptions
{ concurrency?: number; onCompleted?: (name, jobId) => void; onFailed?: (name, jobId, error) => void }. onCompleted wraps the worker's completed event; onFailed wraps failed; for an event without a job, the name reports as "unknown".
JobInfo
{ id: string | undefined; name: string; attemptsMade: number }, the second processor argument.
JobMap / JobProcessors<TJobs> / BulkJobInput<TJobs>
The job-map constraint (object); the per-name handler record; and the addBulk entry union { name; payload; options? }.
QueueWorkerHandle / QueueContext<TJobs>
{ close(): Promise<void> }, and { queueService: QueueService<TJobs> }, the context slice the module provides. Note it is the same context key as @rhythmjs/queue's, which is what makes the two modules drop-in swappable.
