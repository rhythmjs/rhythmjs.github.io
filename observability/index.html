Observability middleware

Request logging, request ids, and server timing for Rhythm routers.

Install #

The package ships three small middlewares for Rhythm routers and handlers. Each module is its own subpath export; there is no root barrel export.

Log requests #

log() wraps the chain and reports a structured LogEntry per request with the method, path, status, and duration in milliseconds. The default sink prints METHOD /path status Nms to the console; pass your own sync or async sink to route entries anywhere.

When downstream throws, the entry is logged with status: 500 and the error, then the error is rethrown, so an exception filter registered outside log still sees it.

Correlate with request ids #

requestId() reuses the incoming x-request-id header or generates a crypto.randomUUID(), sets it on the response header, and extends the context with ctx.requestId via RequestIdContext.

Measure with server timing #

timing() appends a Server-Timing header after next() with the duration of everything downstream, visible in browser devtools. Pass a custom metric name instead of the default app. Multiple layers append their metrics instead of replacing each other.

Compose them #

Register log outermost so it measures and reports everything, then timing, then request-id.
