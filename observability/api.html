API reference

Exports and signatures for the log, request-id, and timing subpaths of @rhythmjs/observability.

@rhythmjs/observability/log #

Returns middleware that measures each request and calls the sink once per request. Without an argument, the default sink prints METHOD /path status Nms to the console. When downstream throws, the sink receives an entry with status: 500 and the error, then the error is rethrown so an outer exception filter still sees it.

LogEntry
The structured entry passed to the sink: method: string, path: string, status: number, duration: number (rounded milliseconds), and error?: unknown, set only when downstream threw.
LogSink
(entry: LogEntry) => void | Promise<void>. Sync or async; an async sink is awaited before the middleware returns.

@rhythmjs/observability/request-id #

Returns middleware that reads the incoming header named by header (default "x-request-id") and reuses its value, or generates a new id with crypto.randomUUID(). The id is set on the response under the same header name and passed downstream as ctx.requestId.

RequestIdContext
{ requestId: string }. The context extension made available to downstream middleware; use it as the type argument of use so handlers see ctx.requestId.

@rhythmjs/observability/timing #

Returns middleware that appends a Server-Timing header after next() resolves, in the form name;dur=N with the downstream duration in milliseconds to one decimal place. The metric name defaults to "app". The header is appended, not replaced, so multiple timing() layers each contribute their own metric.
