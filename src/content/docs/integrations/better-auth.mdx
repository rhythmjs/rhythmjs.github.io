Start from the [template](https://github.com/rhythmjs/template). `src/app.service.ts` stays as it is.

## Install

```bash
bun add better-auth @rhythmjs/better-auth
```

## The Better Auth instance [#auth]

Put the frontend's origin in `trustedOrigins`: Better Auth checks origins itself, separately from CORS. The database is a Bun SQLite file, and `closeAuthDatabase` is what the app module disposes on teardown.

```ts
// src/lib/auth.ts
import { Database } from "bun:sqlite";
import { betterAuth } from "better-auth";

const database = new Database(process.env.AUTH_DB ?? "auth.db");

export const frontendOrigin = process.env.FRONTEND_URL ?? "http://localhost:3001";

export const auth = betterAuth({
  database,
  baseURL: process.env.BETTER_AUTH_URL ?? "http://localhost:3007",
  secret: process.env.BETTER_AUTH_SECRET ?? "rhythmjs-better-auth-example-secret-change-me",
  trustedOrigins: [frontendOrigin],
  emailAndPassword: { enabled: true },
});

export function closeAuthDatabase(): void {
  database.close();
}
```

## Create its tables [#migrate]

`bun run db:migrate` runs this file directly, and `main.ts` runs it at startup.

```ts
// src/lib/migrate.ts
import { getMigrations } from "better-auth/db/migration";
import { auth } from "./auth";

export async function migrate(): Promise<void> {
  const { runMigrations } = await getMigrations(auth.options);
  await runMigrations();
}

if (import.meta.main) {
  await migrate();
  console.log("better-auth tables are up to date");
}
```

## Session middleware from the package [#session]

[`@rhythmjs/better-auth`](https://www.npmjs.com/package/@rhythmjs/better-auth) has three pieces, with the `auth` instance read from `ctx.auth`: the module exports it when you register it (next section).

- `betterAuthModule.forRoot({ auth, path })` mounts `auth.handler` at `path` (default: the instance's `basePath`, else `/api/auth`) and provides `auth`.
- `withSession()` calls `auth.api.getSession` and puts `session` and `user` on the context, both `null` when anonymous.
- `requireSession()` does the same lookup and answers 401 when there is no session. Its type tells the handler that `ctx.session` and `ctx.user` are set.

`session` and `user` have Better Auth's base types. For plugin or custom fields, call `ctx.auth.api.getSession` yourself: it is typed from your instance. The package depends on `@rhythmjs/http` and `@rhythmjs/security` itself, and re-exports `cors` from `@rhythmjs/security/cors` unchanged, so there is nothing else to install.

## The controller guards a route [#controller]

The template's controller gets `AuthContext` and `SessionContext` in its context type, and a `/me` route behind `requireSession()`. Put the guard on the route: a router-level guard narrows the router's context, and that router would then not type-check when mounted.

```ts
// src/app.controller.ts
import { requireSession, type AuthContext, type SessionContext } from "@rhythmjs/better-auth";
import { RhythmRouter } from "@rhythmjs/router";
import type { RhythmHttpContext } from "@rhythmjs/router/adapters/context";
import type { appService } from "./app.service";

export type AppContext = RhythmHttpContext &
  AuthContext &
  SessionContext & {
    appService: typeof appService;
  };

export const appController = new RhythmRouter<AppContext>()
  .get("/", (ctx) => {
    ctx.response.headers.set("content-type", "text/plain");
    ctx.response.body = ctx.appService.getHello();
  })
  .get("/me", requireSession(), (ctx) => {
    ctx.json({
      id: ctx.user.id,
      name: ctx.user.name,
      email: ctx.user.email,
      sessionExpiresAt: ctx.session.expiresAt,
    });
  });
```

For roles, check `ctx.user.role` in a guard of your own: Better Auth's admin plugin keeps a single `role` string on the user.

## The module mounts it [#module]

Order matters. `cors()` comes first, so preflights are answered and Better Auth's own responses carry the headers. The better-auth module then hands everything under `/api/auth` to Better Auth's handler (it uses [`mount`](/http/mount/) underneath) and exports `auth` to the context, which is what `withSession()` and `requireSession()` read. Nothing reaches the context until you export it in the `register` callback. The `provide` closes the database on teardown.

```ts
// src/app.module.ts
import { betterAuthModule, cors, withSession } from "@rhythmjs/better-auth";
import { Rhythm } from "@rhythmjs/rhythm";
import type { RhythmHttpContext } from "@rhythmjs/router/adapters/context";
import { appController } from "./app.controller";
import { appService } from "./app.service";
import { auth, closeAuthDatabase, frontendOrigin } from "./lib/auth";

export const appModule = new Rhythm<RhythmHttpContext>({ name: "app", type: "module" })
  .provide(
    () => ({ appService }),
    () => closeAuthDatabase(),
  )
  .use(cors({ origin: frontendOrigin, credentials: true, allowHeaders: ["Content-Type", "Authorization"] }))
  .register(betterAuthModule.forRoot({ auth, path: "/api/auth" }), (m) => ({ auth: m.auth }))
  .use(withSession())
  .use(appController.middleware())
  .use((ctx) => {
    ctx.response.status = 404;
    ctx.response.headers.set("content-type", "application/json");
    ctx.response.body = JSON.stringify({ success: false, status: 404, message: "Not Found" });
  });
```

```ts
// src/main.ts
import { toFetchHandler } from "@rhythmjs/router/fetch";
import { appModule } from "./app.module";
import { migrate } from "./lib/migrate";

await migrate();

const port = Number(process.env.PORT ?? 3007);

const server = Bun.serve({ port, fetch: toFetchHandler(appModule) });
console.log(`listening on ${server.url}`);
```

## Things to check

- Without the module, `authHandler({ auth })` is the bare mounting middleware; provide `ctx.auth` yourself in that case.
- Better Auth rate-limits its own endpoints; Rhythm middleware does not see requests that `mount` answers.
- Set `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` outside local runs.

The full app, with tests, is [examples/better-auth](https://github.com/rhythmjs/examples/tree/main/examples/better-auth), built from the [template](https://github.com/rhythmjs/template).
