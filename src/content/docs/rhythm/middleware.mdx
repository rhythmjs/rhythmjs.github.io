## Follow the onion

Middleware receives `(ctx, next)`. Awaiting `next()` runs the remaining steps, then resumes the current step. Omitting it stops downstream execution.

```ts
const app = new Rhythm()
  .use(async (_ctx, next) => {
    console.log("before");
    await next();
    console.log("after");
  })
  .use(() => console.log("inside"));

await app.run({});
// before → inside → after
```

## Extend the context

Pass fields to `next(extra)` to merge them into the context. Supply the `use<TExtra>` generic to expose those additions to subsequent middleware; the extra type is not inferred from the body of your callback.

```ts
const app = new Rhythm<{ userId: string }>()
  .use<{ user: { id: string; name: string } }>(async (ctx, next) => {
    await next({ user: { id: ctx.userId, name: "Ada" } });
  })
  .use((ctx) => console.log(ctx.user.name));

await app.run({ userId: "u1" });
```

## Run conditionally [#conditional]

`use(fn, when)` takes a predicate as its second argument. When `when(ctx)` returns `true`, `fn` runs as usual; when it returns `false`, the request skips `fn` and goes straight to `next()`. The predicate receives the context as it stands at that point in the chain, including startup values and anything an earlier `derive()` added, and may be async.

```ts
const app = new Rhythm<{ path: string }>()
  .use(cors(), (ctx) => ctx.path.startsWith("/api"))
  .use(async (ctx, next) => {
    await next();
  });
```

A skipped middleware does not end the chain and does not change the onion order: outer middleware still wrap everything downstream. A predicate that throws rejects the run, like any other middleware failure. Core knows nothing about paths; for HTTP, `matches()` and `routed()` from `@rhythmjs/router/match` build predicates from the request (see the [router API](/router/api/)).

<Callout title="A conditional derive adds nothing to the type">

`use(derive(...), when)` can skip the derive, so its fields may be missing downstream. The overload with a predicate therefore returns the context type unchanged, and the extra fields are not typed on later middleware.

</Callout>

## Handle errors

Register an error-handling wrapper before the handlers it should protect. Wrap `await next()` in a try/catch to handle downstream failures. Use `finally` for per-run cleanup. Calling `next()` more than once in the same middleware dispatch rejects with an error.

```ts
const guarded = new Rhythm().use(async (_ctx, next) => {
  try {
    await next();
  } catch (error) {
    console.error("Pipeline failed", error);
    throw error;
  }
});
```

## Readonly by default

Context properties are deeply readonly at the type level, including arrays, maps, and sets. Function values remain callable. Objects branded with `readonly [RhythmMutable] = true` opt out; the router and CLI response classes use this mechanism.

## Use the dispatcher directly

`compose(middleware)` creates the standalone onion dispatcher. It knows nothing about the startup context.

```ts
import { compose } from "@rhythmjs/rhythm";

const dispatch = compose<{ message: string }>([
  (ctx) => console.log(ctx.message),
]);
await dispatch({ message: "Hello" });
```
