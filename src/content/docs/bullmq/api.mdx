## createQueueService and bullmqModule [#create-queue-service]

```ts
function createQueueService<TJobs extends JobMap>(
  options?: BullmqModuleOptions,
): QueueService<TJobs>;

const bullmqModule: {
  forRoot<TJobs extends JobMap>(options?: BullmqModuleOptions): Rhythm<...>;
};
```

`createQueueService` constructs one BullMQ `Queue` from the options; every `process()` call adds a `Worker` on the same queue name and shared connection. `bullmqModule.forRoot` (module name `bullmq`) provides `{ queueService }` and disposes it on teardown, workers first, then the queue.

<DefList>
<Def sig="BullmqModuleOptions" id="bullmqmoduleoptions">`{ name?: string; connection?: ConnectionOptions; prefix?: string; defaultJobOptions?: JobsOptions }`. `connection` defaults to `{ host: "127.0.0.1", port: 6379 }`; `prefix` is BullMQ's Redis key prefix.</Def>
</DefList>

## QueueService\<TJobs\> [#queue-service]

```ts
interface QueueService<TJobs extends JobMap> {
  add<K extends keyof TJobs & string>(name: K, payload: TJobs[K], options?: JobsOptions): Promise<string | undefined>;
  addBulk(jobs: BulkJobInput<TJobs>[]): Promise<(string | undefined)[]>;
  schedule<K extends keyof TJobs & string>(name: K, repeat: RepeatOptions, payload: TJobs[K], options?: JobsOptions): Promise<void>;
  unschedule(name: keyof TJobs & string): Promise<void>;
  process(processors: JobProcessors<TJobs>, options?: ProcessOptions): QueueWorkerHandle;
  counts(): Promise<Record<string, number>>;
  close(): Promise<void>;
  readonly queue: Queue;
}
```

<DefList>
<Def sig="add(name, payload, options?)" id="add">`queue.add` with the typed payload as job data; resolves to BullMQ's job id (`string | undefined`).</Def>
<Def sig="addBulk(jobs)" id="addbulk">`queue.addBulk`, mapping each entry's `payload` to `data` and `options` to `opts`; resolves to the ids in order.</Def>
<Def sig="schedule(name, repeat, payload, options?)" id="schedule">`queue.upsertJobScheduler(name, repeat, template)` - the scheduler id is the job name, and the template carries the payload and options for each spawned job. Calling it again with the same name replaces the schedule.</Def>
<Def sig="unschedule(name)" id="unschedule">`queue.removeJobScheduler(name)`.</Def>
<Def sig="process(processors, options?)" id="process">Creates a BullMQ `Worker` on the queue name with the shared connection/prefix and `options.concurrency`. The worker's processor dispatches by `job.name` to the typed handler, passing `(payload, { id, name, attemptsMade })`; an unregistered name throws `no processor registered for job "name"`, which lands in BullMQ's retry/failed flow. Returns a handle whose `close()` closes the worker and deregisters it.</Def>
<Def sig="counts()" id="counts">`queue.getJobCounts()`: BullMQ's state counts (waiting, active, delayed, completed, failed, …).</Def>
<Def sig="close()" id="close">Closes every open worker, then the queue and its connection.</Def>
<Def sig="queue" id="queue">The underlying BullMQ `Queue` instance, for everything the facade does not cover.</Def>
</DefList>

## Options and types

<DefList>
<Def sig="JobsOptions / RepeatOptions / ConnectionOptions" id="jobsoptions">Re-exported from `bullmq` unchanged; the facade adds no translation layer. `JobsOptions` covers `delay`, `attempts`, `backoff`, `priority`, `removeOnComplete`/`removeOnFail`, `jobId`, `lifo`, deduplication, and the rest; `RepeatOptions` covers `pattern`, `every`, `tz`, `limit`, …</Def>
<Def sig="ProcessOptions" id="processoptions">`{ concurrency?: number; onCompleted?: (name, jobId) => void; onFailed?: (name, jobId, error) => void }`. `onCompleted` wraps the worker's `completed` event; `onFailed` wraps `failed`; for an event without a job, the name reports as `"unknown"`.</Def>
<Def sig="JobInfo" id="jobinfo">`{ id: string | undefined; name: string; attemptsMade: number }`, the second processor argument.</Def>
<Def sig={"JobMap / JobProcessors<TJobs> / BulkJobInput<TJobs>"} id="jobmap">The job-map constraint (`object`); the per-name handler record; and the `addBulk` entry union `{ name; payload; options? }`.</Def>
<Def sig={"QueueWorkerHandle / QueueContext<TJobs>"} id="queueworkerhandle">`{ close(): Promise<void> }`, and `{ queueService: QueueService<TJobs> }`, the context slice the module provides. Note it is the same context key as @rhythmjs/queue's, which is what makes the two modules drop-in swappable.</Def>
</DefList>
