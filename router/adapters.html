HTTP runtime adapters

Serve Rhythm HTTP pipelines on Bun, Node, and Deno.

Bun HTTP #

The fetch adapter accepts a Rhythm host app and returns an async Request-to-Response handler. Routers mount into the host via use(router.routes()) and are never served directly.

Node HTTP #

The Node adapter converts IncomingMessage to Request and streams the resulting response to ServerResponse.

toNodeHandler(app, options?) accepts bodyLimit in bytes. By default, bodies for methods other than GET and HEAD are buffered before the pipeline runs, with a limit of 1,048,576 bytes (1 MiB). Oversized requests receive HTTP 413 and a Connection: close header.

Use { bodyLimit: false } for an unbuffered request stream with no size limit. In that mode, the handler must consume the body to avoid leaving unread input on a keep-alive connection.

The adapter logs unexpected errors and sends HTTP 500 if headers have not been sent; otherwise it destroys the response connection. Response bodies stream back to the client, and multiple Set-Cookie headers are preserved.

Deno HTTP #

Deno re-exports the same Web-standard fetch adapter.

Runtime setup #

These snippets assume an already-configured HTTP app. Adapter availability does not change package distribution: the current manifests export TypeScript source from private workspaces. Outside Bun, configure your TypeScript execution and workspace resolution for the chosen runtime.

Adapters do not automatically tear down your application. Arrange cleanup at shutdown, and explicitly close flat-mounted child instances that own resources.
