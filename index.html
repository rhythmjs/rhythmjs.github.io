Introduction

A small foundation for composable applications.

What Rhythm is #

Rhythm is a minimal, type-safe composition kernel for JavaScript and TypeScript. Combine onion-style middleware, shared providers, and encapsulated modules into a pipeline you can understand from top to bottom.

The core has no HTTP layer or command router. Those live in separate packages, built on the same primitives.

@rhythmjs/rhythmBuild a pipeline

Compose middleware and manage shared dependencies.

 @rhythmjs/routerHandle a request

Route Web-standard requests with runtime adapters.

 @rhythmjs/cliRun a command

Compose commands, flags, and interactive prompts.

 @rhythmjs/middlewareValidate a request

Schema validation, interception, and exception filters.

@rhythmjs/httpManage the session

Cookies, sessions, ETags, timeouts, and body limits.

 @rhythmjs/securityGuard the edges

CORS, CSRF protection, and secure headers.

 @rhythmjs/observabilityWatch it run

Request logging, request ids, and server timing.

A first look #

Providers initialize once. Middleware runs for each input. The resulting context carries your input and dependencies through the pipeline.

Small by design #

  • Onion execution. Work before and after downstream middleware with await next().
  • Typed composition. Providers and explicit context extensions travel through the fluent API.
  • Managed dependencies. Resolve providers in declaration order and dispose in reverse.
  • Explicit boundaries. Keep module fields private until you choose to export them.
Published on npm

The packages are published under the @rhythmjs organization at version 0.0.1. Every module is exported by its own subpath, such as @rhythmjs/middleware/validate; there are no barrel exports.

Start building #

Begin with the quick start, read the philosophy behind the design, or clone the starter template for a Nest-style skeleton. If you already know the model, jump to the API reference.
