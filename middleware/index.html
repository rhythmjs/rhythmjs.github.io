Validate, intercept, filter

Request validation, response transformation, and exception handling for Rhythm routers.

Install the package #

@rhythmjs/middleware is a middleware collection for Rhythm routers and handlers. Each module lives on its own subpath export, /validate, /intercept, and /filter; there is no root barrel export.

Validate requests #

validate(target, schema) checks one part of the request against any Standard Schema v1 schema, such as zod, valibot, or arktype. The target is "body" for the JSON request body, "query" for URL search params (repeated keys become arrays), or "param" for route params matched by the router.

On success the schema's output is merged into the context as ctx.valid[target], so chained validators compose. The Validated<Target, Schema> type plugs into a route handler's TExtra parameter to type ctx.valid. On failure the chain short-circuits with a 400 JSON body of type ValidationFailure: { "success": false, "target": "body", "issues": [...] }.

Intercept responses #

intercept(schema) is the response-side counterpart of validate. It runs after next(), in onion order: only successful (2xx) string bodies are intercepted, parsed as JSON, passed through the schema, and the schema's output is written back as the response. Error responses and non-string bodies pass through untouched.

Because only declared fields survive the schema, it doubles as a serialization guard that never leaks fields such as password. If the response does not match the schema, the request fails with 500 and an InterceptFailure JSON body: { "success": false, "issues": [...] }.

Filter exceptions #

filter(onError?) wraps the rest of the chain in a try/catch and turns anything thrown downstream into an HTTP response. Register it first, before any routes, so it forms the outermost onion layer and sees every error.

A thrown HttpError(status, message, details?) maps to that status with a JSON body of type FilterFailure. Any other thrown value maps to a generic 500 with the message "Internal Server Error"; the original error message is never leaked to the client. Passing an onError(error, ctx) hook replaces the default mapping entirely, so it can log, map domain errors to statuses, or rethrow.

Compose them #

The three modules compose freely on one router. filter goes first, error responses are non-2xx so intercept skips them, and validate runs per route ahead of the handler.

See the API reference for every export on the three subpaths.
